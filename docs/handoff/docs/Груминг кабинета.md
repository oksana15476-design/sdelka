## Что в кабинете уже верно

Это база, её не трогаем.

- Кабинет **один**, роль — свойство сделки. Ни «кабинета покупателя», ни «кабинета продавца».
- Четыре машины состояний с идентификаторами из кода: транш (12), вывод (6),
  реквизиты получателя (6), заморозка (3 цели).
- Мультивалютность: валюта сделки (три) × валюта перевода (топ-10). При совпадении
  конвертационный слой исчезает целиком.
- Экран сделки: деньги, требуемое действие и срок — одна карточка. Расчёт, объект и
  стороны под раскрытием.
- Лента с метками «кто держит мяч».
- ⚖-слот о праве отзыва отделён от закрытой кнопки вывода.
- Мобильная верстка: бургер и выдвижная панель, контейнерные запросы, цели ≥44 px.
- Терминология по глоссарию: получатель, плательщик, поручение, банковский день,
  объект сверен с реестром, счёт номинального держания.

## P0 · Расхождения с реализацией

Пока не закрыты, макет и код говорят на разных языках.

### 1. Восемнадцать состояний денег вместо двенадцати статусов транша

Кабинет строит блок «где деньги» на статусах домена. Но интерфейс обязан показывать
проекцию `M-01…M-18` из `apps/web/src/view/money-state.ts`: у приложения есть состояния,
которых у домена нет, и все они — про чужие деньги.

| Нет в макете | Что это | Почему нельзя пропустить |
|---|---|---|
| `M-02 transferDeclared` | Заявлен перевод | Заявление стороны, не банковское событие. Самый частый повод спора «я же отправил» |
| `M-03 unidentified` | Поступление не опознано | Деньги пришли, но к сделке не отнесены и балансом не считаются |
| `M-04 heldThirdParty` | Платёж третьего лица | Остановлен; получателю детали не раскрываются |
| `M-05 onAccountFx` | Внесено, не конвертировано | Единственное состояние, где от плательщика требуется решение о курсе |
| `M-07 partiallyFunded` | Недобор | Нужен размер недобора и срок добора |
| `M-08 overfunded` | Излишек | Излишек — в свободную часть немедленно, не после закрытия |
| `M-13 payoutUnknown` | Ответа банка нет | Повтор поручения запрещён; закрывает сверка, не таймер |
| `M-17 frozen` | Заморожено | Есть как кнопка-демо, не как состояние денег |

**Объём:** переписать `TRANCHE` на восемнадцать записей с идентификаторами `money-state.ts`,
добавить вставки в ленту для `M-03`, `M-04`, `M-13`.

### 2. Три текста на состояние, а не один

Одно событие описывается по-разному для платящей стороны, получающей и оператора.
Сейчас в кабинете один текст, который показывается плательщику.

| Роль | Ключи |
|---|---|
| Платящая | `deal.paying.where.<state>.{title,body,amountLabel}` |
| Получающая | `assurance.state.<state>.{title,subtitle}` |
| Оператор | `ops.money.<state>.{label,note}` |

Правило: **одно событие — одни и те же слова у обеих сторон**. Итоги различаются, события нет.

### 3. Тексты взять из `DRAFT-money.md` дословно

Мои строки — собственные черновики. В репозитории лежат прошедшие главреда, с ключами и
разобранными ошибками. Перенос — не редактура, а замена по ключам.

### 4. ⚖-слоты идут одним пакетом

Границу отзыва несут **семь** строк, а не три. Если юрист сдвинет границу, а поправят три —
в интерфейсе будут жить две границы одновременно.

Список: `deal.paying.where.reserved.revocation`, `…submitted.revocation`,
`…releasePending.revocation`, `assurance.limits`, `assurance.revocationClosed`,
`deal.receiving.timeline.onAccount.detail`, `deal.receiving.timeline.submitted.detail`.

### 5. Числа только слотами

В макете суммы и даты вписаны в текст. По красной линии №4 они приходят с сервера в целых
минорных единицах и форматируются через `Intl`. Отдельно: согласование с числительным
(«1 000 ₾ уйдут») — сумма выносится строкой над текстом, а не внутрь предложения.

## P2 · Качество

| Что | Проверка |
|---|---|
| Бюджеты длины | Заголовок ≤44, тело ≤240 и ≤3 предложения, чип ≤32, ⚖-слот ≤200. Мерить на грузинском, он длиннее русского в полтора раза |
| Грузинский | Есть навигация и ключевые строки, остальное падает на русский. Три версии обязаны быть содержательно эквивалентны — это требование закона |
| Список сделок | Пересобрать с группировкой «требует вашего действия» / «идут своим ходом»; сейчас плоский |
| Панель прототипа | Держать вне продуктового слоя, из мобильной верстки скрыта — оставить так |
| Иконки | Правила есть, набора нет; сейчас геометрические глифы-заглушки |

## Порядок работ

1. **P0.1 + P0.3** — восемнадцать состояний с текстами из `DRAFT-money.md`. Один проход,
   потому что состояния и их текст неразделимы.
2. **P0.2** — вид получающей стороны на тех же состояниях.
3. **P0.4 + P0.5** — ⚖-слоты пакетом и вынос чисел в слоты.
4. **P1** — рассрочка, затем пополнение по `INTAKE.md`, затем мастер проверки.
5. **P2** — бюджеты, грузинский, список сделок.

**Приёмка каждого прохода:** на каждом экране есть ответ на «где мои деньги»; ни одного
второго имени участника; ни одной цели меньше 44 px; ни одной формулировки вины стороны;
границы отзыва в интерфейсе ровно одна.
