# Yandex Direct — сборка рекламных кампаний

Использовать для: планирования и сборки кампаний Директа, аудита, оптимизации,
бюджетов, ключей, минус-слов, адаптивных объявлений, поисковых запросов, Wordstat
и решений, завязанных на Метрику.

> **Контекст проекта обязателен.** Перед сборкой заполни и прочитай
> [`references/PRODUCT_CONTEXT.template.md`](references/PRODUCT_CONTEXT.template.md)
> — там номер счётчика, primary-конверсия, кластеры ядра, минус-слова, лендинг и
> стратегия старта. Скопируй шаблон в `references/PRODUCT_CONTEXT.md` (в
> `.gitignore`, если данные чувствительные) и держи его источником правды.
> **Не выдумывай эти данные** — нет заполненного контекста, попроси владельца.

## Контур исполнения (выбрать путь ДО сборки)

Публичного «write»-скилла к API здесь нет намеренно (без платных посредников).
Три пути:

- **A. Директ Коммандер (основной, владелец работает сам).** Агент готовит
  структуру + семантику + минус-слова + тексты, выгружает в **XLSX формата
  Коммандера**, владелец импортирует и отправляет. См. раздел «Экспорт в Коммандер».
- **B. Ручная сборка в кабинете (headed-браузер).** Владелец логинится в Яндекс
  сам (2FA), агент навигирует и заполняет под гардрейлами «Браузерного контура».
  Годится для верификации, точечных правок, первого черновика без оплаты.
- **C. (Опционально) свой Direct MCP на своём OAuth.** Открытые серверы
  (напр. `@theyahia/yandex-direct-mcp`) + токен Директа в `config/.env`
  (в `.gitignore`, НЕ коммитить). Тогда действуют «v3/MCP»-правила ниже.

## Современная сборка (ЕПК по умолчанию)

Строить управляемые кампании ЕПК, не legacy TEXT:

```text
Единая перфоманс-кампания (UNIFIED_CAMPAIGN)
 └─ группа UNIFIED_AD_GROUP
     ├─ ключевые фразы (батчем) + минус-фразы
     └─ адаптивное объявление (несколько заголовков/текстов)
         └─ модерация — ТОЛЬКО после явного подтверждения владельца
```

Legacy `TEXT_CAMPAIGN`/text-группы — только для старых текстовых сценариев; если
используются, явно сказать, что это legacy-путь, и перечитать фактический тип после
создания. Бюджеты — **в рублях**, не в микроединицах.

## Гардрейлы (обязательны на всех путях)

- **Поиск по умолчанию.** РСЯ/сети включать только по явной просьбе владельца.
- **Read before write.** Сначала прочитать текущее состояние, потом менять.
- **План + подтверждение.** Перед любой записью показать точный план и дождаться
  **явного текстового «да»**. Изменения **цели, стратегии или бюджета >30%** —
  отдельное подтверждение.
- **Не выдумывать** ID, статистику, цели, счётчики, бюджеты, частотность Wordstat.
  Нет данных — прочитать или сказать «нет данных», не подставлять.
- **Финансы — на владельце.** Пополнение баланса, ввод платёжных данных, запуск с
  реальным расходом — делает **владелец сам**. Агент платёжные данные не вводит.
  Овердрафт/автопополнение не включать без «да».
- **Секреты — только из окружения.** OAuth-токены и логины кабинета не коммитить;
  `config/.env` держать в `.gitignore`.
- **Тексты — через редактуру.** Любой текст объявления идёт: `content-creation`/
  `draft-content` (черновик) → `brand-review` (главред: голос, без ложных обещаний,
  дисклеймеры) → юридическое ревью (**38-ФЗ «О рекламе»** и отраслевые требования)
  — ДО модерации.

## Браузерный контур (путь B) — правила

Применять, только когда клиент умеет управлять уже авторизованным браузером и
владелец прямо попросил работать в веб-интерфейсе. Это не API-операция.

- Сначала **прочитать** текущее состояние в интерфейсе.
- **Не** запрашивать, не вводить и не сохранять логины, пароли, одноразовые коды,
  платёжные данные. Если сессия не авторизована — попросить владельца войти самому
  и **остановиться**.
- Перед любым кликом, меняющим контент, публикацию, бюджет, ставку, цель, стратегию,
  статус, модерацию или расход, — показать точный план и дождаться явного «да».
  Просьба «открой/проверь страницу» не разрешает сохранять изменения.
- Ничего не сохранять, не публиковать, не запускать и не останавливать автоматически.
  После подтверждённого действия — перечитать состояние и проверить факт результата.

## Лендинги и посадочные

- API Директа **не** редактирует блоки `clients.site`/турбо-страниц — только веб.
- Если лендинг живёт в репозитории, правки контента/офферов делаем **в коде**
  (дизайн-агент + копирайтер→главред), а не в кабинете Директа.

## Семантика и спрос

- Спрос — скилл **`yandex-wordstat`** (лимит **100 req/hour**: полный прогон ядра
  планировать одним заходом, а не итерациями).
- Группировка — **`keyword-clustering`**: один кластер = одна группа = один JTBD.
- Высокая частотность ≠ целевой трафик: широкие информационные «головы» чистим
  минус-словами или не берём вовсе (список — в `PRODUCT_CONTEXT.md`).

## Привязка Метрики и разметка

- Счётчик проекта добавить в настройках кампании (со стороны Директа) — этим и
  «связывается» Метрика↔Директ. Проще всего, когда логин Метрики и Директа один;
  иначе выдать гостевой доступ.
- Включить **автопометку `yclid`** + единый **UTM-шаблон** (source/medium/campaign/
  content/term). Сквозная аналитика в Директе появится после привязки счётчика.

```text
utm_source=yandex&utm_medium=cpc&utm_campaign={campaign_id}&utm_content={ad_id}&utm_term={keyword}&utm_referrer={source}&yclid={yclid}
```

- Замер и конверсии читать скиллом **`yandex-metrika`** (цели, `get_campaign_stats`,
  поисковые запросы; attribution — как в кабинете).
- **Выбор конверсии под оптимизацию:** брать цель, которая реально стреляет.
  Если продаж/оплат ещё нет (0 достижений), автостратегии на них не обучатся —
  стартовать на микроконверсии (заявка, форма) с малым бюджетом.

## Read-чеклист (аудит перед изменениями)

- Кампании (нужные `states`/`field_names`), группы, объявления/адаптивные, ключи.
- Автотаргетинг/категории. Статистика кампаний и поисковые запросы (период +
  attribution). Wordstat — без `client_login`/`connection_id`.

## Экспорт в Директ Коммандер (путь A)

Готовим кампанию как таблицу и отдаём владельцу для импорта. Колонки (группами):
кампания (тип, название, регионы, стратегия, дневной бюджет), группа (название),
фраза (ключевая), минус-фразы, адаптивное объявление (заголовок 1/2, текст,
отображаемая ссылка, ссылка с UTM), ставки. **Точный шаблон — из собственного
экспорта Коммандера** (File → экспорт кампании в XLS): взять его как эталон колонок,
не выдумывать формат. Генерацию таблицы делать скиллом **`xlsx`**.

## Отчёты

Отчёт по итогам — `performance-report`; выгрузка в Google Sheets/Docs (если есть
доступ) — через `export-ad-reports`. Данные — из `yandex-metrika`/кабинета, не из головы.
